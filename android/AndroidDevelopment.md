# Android Development Map

## 목표

Android 앱은 iPhone 앱과 같은 기능과 CSV 파일 구조를 공유한다.

## 기본 방향

- 앱 이름: `PDB`
- 프로젝트 위치: `android/`
- 앱 ID: `com.pdb.younggwang.local`
- 서버 사용 금지
- 차량 DB는 기기 로컬 저장소에 저장
- Android 자동 백업은 비활성화해 차량 DB가 시스템 백업으로 외부 이전되지 않게 한다.
- CSV 형식은 `ios/ParkingLocalApp/Data/CSVFormat.md`와 동일하게 유지
- iOS 앱과 동일하게 카메라 화면을 첫 화면으로 사용

## 현재 구현

- 카메라 시작 화면
- CameraX 기반 실시간 카메라 프리뷰
- 번호판 가이드 UI
- iPhone 앱과 같은 카메라 UI
- 하단 원형 촬영 버튼
- 촬영 버튼 좌측 키보드 모양 수동 입력 버튼
- 좌측 상단 OCR 디버그 이력 버튼
- 우측 상단 설정 버튼
- 촬영 버튼, ML Kit Korean Text Recognition OCR, 수동 입력 흐름
- 차량 등록과 수정
- 차량 번호 중복 시 기존 유지 또는 신규 저장 선택
- 차량 번호 정규화와 한국 번호판 형식 경고
- 차종 이력 기반 최근 차종 표시
- 차량 통계
- 주차 공간 현황과 세부 수량 수정
- CSV 내보내기와 불러오기
- CSV 가져오기 중 차량 번호 충돌 시 기존 유지 또는 가져온 값 저장 선택
- 스와이프 기반 카메라와 통계 화면 전환
- 핀치 줌
- 핀치 줌은 카메라 화면에서만 처리하고, CameraX 줌 배율 범위와 비정상 값을 방어해 실제 기기 크래시를 방지한다.
- 핀치 줌 후 손가락을 뗄 때 발생하는 단일 터치 종료 이벤트는 스와이프 화면 전환으로 처리하지 않는다.
- OCR 이미지 디코딩, 크롭, 원근 보정, 대비 보정은 백그라운드 전용 스레드에서 처리한다.
- 반복 UI 생성 코드는 `ui/PdbViewFactory.kt`로 분리한다.
- 카메라 권한 요청과 CSV 파일 선택은 Activity Result API로 처리한다.
- `android:allowBackup="false"`로 로컬 저장 원칙과 개인정보 설명을 맞춘다.

## UI 원칙

- 모든 목록 화면은 `ScrollView`를 사용해 세로 스크롤을 막지 않는다.
- 버튼은 최소 48dp 높이를 유지한다.
- 통계 카드는 2열 또는 3열 GridLayout으로 배치하되 최소 높이를 둔다.
- 긴 한글 텍스트는 한 줄 고정 대신 여러 줄 표시를 허용한다.
- 카메라 화면의 주요 액션은 하단에 고정하고 서로 겹치지 않게 여백을 둔다.
- 카메라 버튼은 홈 인디케이터와 겹치지 않도록 하단 안전영역보다 위에 배치한다.
- 수동 입력 버튼은 촬영 버튼을 가리지 않도록 촬영 버튼 좌측에 분리 배치한다.
- UI 버튼 요소는 다른 버튼, 가이드 프레임, 상태 문구를 가리면 안 된다.
- 핀치 줌 제스처는 통계, 설정, 목록 화면의 스크롤과 충돌하지 않아야 한다.
- 핀치 줌 제스처가 끝난 직후에는 카메라와 통계 화면 전환이 실행되면 안 된다.
- 카메라 화면은 번호판 가이드 영역 외부를 어둡게 마스킹하고, 마스크의 투명 창과 가이드 프레임을 같은 좌표 계산으로 그린다.

## OCR 계획

현재 Android OCR은 Google ML Kit Korean Text Recognition과 번호판 전용 후처리로 연결되어 있다.

현재 흐름:

- CameraX로 이미지 캡처
- 촬영 이미지를 EXIF 회전 기준으로 정규화
- 전체 이미지와 번호판 가이드 주변 크롭 후보 생성
- 각 후보에 대비 강화와 흑백 보정을 적용한 추가 후보 생성
- 가이드 크롭에는 상단/하단 원근 보정 후보와 좌우 회전 보정 후보를 추가
- ML Kit Korean Text Recognition을 후보 이미지별로 실행
- 처리한 Bitmap은 후보별 OCR 완료 후 즉시 해제해 메모리 압박을 줄임
- 공백, 하이픈, 점 제거
- 숫자 위치 OCR 오인식 보정
- `숫자 2~3자리 + 한글 1글자 + 숫자 4자리` 후보 추출
- 뒷 4자리만 인식된 경우에는 신규 번호로 확정하지 않고 기존 DB와 유일하게 매칭될 때만 보정
- 후보별 점수와 DB 보정 여부를 OCR 디버그 이력에 기록

다음 단계에서는 실제 실패 이미지를 저장해 크롭 위치와 대비 값을 현장 데이터 기준으로 조정한다.
